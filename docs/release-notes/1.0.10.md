# VNDB 1.0.10

搜索页多了「以图搜作品」：上传一张截图或插画，识别出作品名并直接跳到 VNDB 的作品页。别的应用（相册、QQ、文件管理器……）里看到喜欢的图，也可以直接点「分享」→「以图搜作品」，不用再手动打开 App 选图。另外，内置浏览器里的下载链接现在会交给手机上的下载管理器（1DM+ / ADM）接管。

## 新增

- **以图搜作品**：搜索页（底部「搜索」标签）搜索框下方新增入口。选一张图，App 会先在本地压缩再上传识别，返回作品名与角色名，并自动用作品名去 VNDB 反查对应条目，列出封面、标题、原名与年份，点一下直接进作品详情页；没匹配上的作品可以一键转到 VNDB 关键词搜索
- **识别结果带上置信度提示**：整体置信度偏低的识别结果会标注「置信度较低」，AI 生成的图也会单独提示
- **从其他应用分享图片直接以图搜作品**：系统分享面板里本应用多了一个「以图搜作品」入口（显示为「VNDB / 以图搜作品」两行）。从相册、QQ、浏览器等任何能分享图片的应用里选中图片分享过来，App 会自动跳到「以图搜作品」页并开始识别，一路列出作品与 VNDB 条目
- **冷启动、热启动都支持**：App 没在运行也没关系，从分享面板直接拉起来即可；App 已经在后台时分享，则回到前台后自动接上。单张图片与多张图片的分享都支持（多张时取第一张识别）

## 变更

- **内置浏览器的下载交给下载管理器**：以前在内置浏览器里点下载链接没有任何反应（WebView 默认不处理下载，插件的下载支持也是关的）。现在下载请求会优先交给手机上装的 1DM+ / ADM，由它们接管下载；没装下载管理器时退回系统默认处理器，仍然不行才由内置浏览器自己落盘。行为与「检查更新」里的 APK 下载一致
- **下载管理器可见性声明**：`AndroidManifest.xml` 的 `<queries>` 补上 1DM+ / ADM 的包名，Android 11+ 才能正确定位到它们
- **分享入口与桌面图标分开**：分享面板里的入口名是「以图搜作品」，桌面上的图标仍然是「VNDB」。用的是 `activity-alias`，不影响原有的启动方式与数据

## 修复

- **内置浏览器里点下载没反应**：见上文，下载事件不再被静默丢弃
- **分享图片进来后停在首页**：不同应用往分享 Intent 里塞图片的位置并不统一（可能是单个 Uri、也可能是 Uri 列表），原先只按 action 分支取，遇到对不上的组合就取不到图。现在四种位置依次兜底，实测从相册、QQ、分享面板分享单图/多图都能正常识别

**升级提示**

- 支持从 1.0.7 / 1.0.8 / 1.0.9 直接覆盖安装（统一签名证书 `d4:a228ca…ef76e`）。
- **1.0.5 及更早**的包是 CI 临时密钥签的，签名对不上，需要先卸载再装（卸载会清掉本地数据）。
- 包名 `com.vndb`，versionCode 10010。
- 「以图搜作品」的图片识别由 [AnimeTrace](https://ai.animedb.cn/) 提供，识别在服务端完成。
